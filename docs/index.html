4.1 交互设计要点

降低认知负担

  • 单页纵向排布，跟着卡片顺序从上往下就是完整流程
  • 每张卡片配一句「这一步在干什么」的提示语
  • 产品档案解析后逐项渲染成可编辑字段，不做黑盒

判定结果可读性

  • 状态色语义统一：绿＝通过、黄＝提醒、红＝需修改
  • 每条判定都引用脚本原文作为证据，结论不悬空
  • 判定理由分要点呈现，结论句高亮，扫读即可抓住重点

人机协同机制

  • 每一行判定都保留人工改判下拉框与理由输入框
  • 机器判定与人工判定并列展示，不一致处标黄
  • 「本轮判定仅供参考」的定位在界面上明确写出

产出可追溯

  • 提交后生成《人工审核表》并落盘 JSON ＋ Markdown 两份
  • 表格含脚本原文，可脱离程序独立阅读
  • 改判理由是下一轮提示词迭代的直接输入

A3 核心卖点通过 方案与需求对应：除味、安全性、性价比诉求均被方案回应；卖点覆盖 5 项：根源除味、非以香盖臭、植物萃取、人群友好、大牌平替 可补充倒置设计与香型寓意，强化工艺与情绪价值记忆点 待选▾ 理由（选填）
A4 事实与证据通过 存在合格证据：他人反馈型（"朋友进门第一眼就问链接"）；无超范围宣称：全部表述与产品档案口径一致 可补充检测数据提示，增强技术可信度 待选▾ 理由（选填）
A5 行动引导通过 结尾含明确购买指令："直接入手"指向购买行为，且承接前文需求构成完整行动召唤 可强化入口提示（如"链接已放左下角"），提升点击转化 待选▾ 理由（选填）
A6 转化逻辑提醒 五环节均在场，痛点弱在场：钩子/方案/证据/指令明确，痛点仅以需求句形式弱存在 → 本维至多提醒 将需求句升级为具象痛点并前置至钩子之后，主链路即完整 待选▾ 理由（选填）

每行判定旁均有人工改判下拉框与理由输入框，与机器判定不一致的格子会高亮提示；提交后自动生成《人工审核表》留档。

整体判定（规则层＋AI 层合并推导）

需修改　Needs Revision

推导过程：规则层 R3 命中风险词「第一」→ 直接进入「需修改」档；同时 AI 层 A1／A2／A6 三维度为「提醒」。 此处正是工具的设计立场——风险词命中不由模型裁量，先拦下来，交给人判断是否属于误伤（如"第一印象"这类固定搭配）。

人工判定：需修改▾ 人工理由：R3 属固定搭配可放行，但 A2 痛点缺失影响转化主链路，维持「需修改」
